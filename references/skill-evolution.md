# Skill Evolution

Use this note inside the tool-improvement axis of `completion-learn`.

The goal is to decide whether tool improvement should happen by:
- extending an existing skill
- adding a second complementary skill
- optimizing an existing skill without changing the boundary
- doing nothing for now

## Questions

1. Was the main failure caused by a missing skill boundary or by a weak existing skill?
2. If a skill already exists, is the real issue routing, examples, references, workflow, or trigger wording?
3. Would a second complementary skill reduce coupling better than overloading the current one?
4. Is this pattern stable enough to deserve a reusable tool change at all?

## Preferred Order

Prefer this order unless evidence says otherwise:

1. optimize an existing skill
2. extend an existing skill
3. add a second complementary skill
4. no skill change

## Output Shape

Keep it short:

- `Problem in current tooling`
- `Best move`
- `Why`
- `Smallest next change`
