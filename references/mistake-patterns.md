# Mistake Patterns

Use one or two labels when converting a finished task into reusable learning. The goal is to name the pattern, not to sound academic.

## Framing Drift

The task started with a fuzzy or overloaded objective, and work moved before the target was cleanly bounded.

## Verification Gap

A claim was treated as done before a verifier or real-world check confirmed it.

## Assumption Debt

Too many unstated assumptions accumulated and later had to be paid back through rework.

## Premature Optimization

Work optimized for elegance, speed, or completeness before the stable path was clear.

## Tool Blindness

The right tool existed, but its output was not used early enough or read carefully enough.

## Context Leakage

Old context, stale summaries, or mixed threads polluted the current decision.

## Boundary Blur

Ownership, module boundaries, or task boundaries were not explicit enough.

## Evidence Weakness

An argument or recommendation sounded plausible but lacked enough concrete support.

## Recovery Pattern

A mistake was corrected through a reusable recovery move worth standardizing next time.

## How To Use

For each chosen pattern, say:
- what triggered it here
- how it showed up
- what guardrail would catch it earlier next time
