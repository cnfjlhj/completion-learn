# Sample Output

Use this as a style anchor for the default no-argument `completion-learn` mode.

The exact content should change with the task. The point is the shape: short, direct, and clearly useful on the next task.

## Sample

`Top lesson`
You moved faster once the task stopped being treated as "fix everything" and was reframed into one concrete bottleneck.

`You: Keep`
Keep the habit of pausing to restate the real bottleneck before changing files.

`You: Stop`
Stop carrying five improvement ideas at once when only one of them is actually on the critical path.

`Collaboration: Improve`
Default to one short global-status update whenever the work crosses into a new phase. That gives the human enough visibility without forcing them to steer every step.

`Tool: Improve`
The tool stack needs a stronger recovery path here. Add or tighten the skill/checklist that handles this failure mode so the next run does not depend on memory.

`Durable rule`
When the task feels wide, narrow the bottleneck before increasing effort.

`Next drill`
On the next similar task, spend the first 3 minutes writing one sentence each for: bottleneck, verifier, and stop condition.

`Skill evolution`
Best move: optimize the existing skill first. The boundary already exists; the weakness is in the trigger/examples/references, not in the lack of a new skill.

## Notes

- The self axis comes first.
- The collaboration axis comes before tool evolution.
- Tool evolution should stay concrete and small unless there is clear evidence for a new skill.
- Prefer one strong recommendation per axis over bloated coverage.
