# Question Bank

Use these questions to deepen a `completion-learn` debrief. Do not answer all of them. Pick the smallest set that sharpens the lesson.

## Core Questions

1. What was the real bottleneck, not just the visible symptom?
2. Which assumption turned out false, incomplete, or too vague?
3. What should have been verified earlier?
4. What was done well enough that it should become default behavior?
5. What should be practiced next rather than merely remembered?
6. If the user could keep only one improvement from this task, what should it be?
7. What should the user stop doing because it repeatedly creates drag?

## Three-Axis Questions

1. What should the user personally keep, stop, or practice next?
2. What communication or operating pattern between user and tool should become default?
3. What inside the tool stack should evolve so the same work becomes cheaper or safer next time?
4. Is the right tool improvement an existing skill upgrade, a second complementary skill, an optimization pass on an existing skill, or no skill change at all?

## Debugging Questions

1. What observation actually ruled out the wrong hypotheses?
2. What log, test, or probe would have shortened the search by half?
3. Was the bug in code, configuration, environment, or mental model?
4. Which fix removed the cause instead of only the symptom?

## Design Questions

1. Which boundary was carrying too many responsibilities?
2. What simplification would have preserved behavior with less coupling?
3. Which tradeoff was accepted, and was it explicitly justified?
4. What would break first if this design were extended?

## Workflow Questions

1. Where did sequencing help or hurt?
2. Which checkpoint or backup saved risk?
3. What should become a standard precheck or postcheck?
4. Which part of the workflow was repeated enough to justify a template or skill?

## Collaboration Questions

1. Which phrasing clarified the task fastest?
2. Where did the user and agent have different implied definitions of "done"?
3. What update would have given better global visibility earlier?
4. Which handoff detail mattered most?

## Research-Writing Questions

1. Which claim was strong because the evidence was concrete?
2. Which argument sounded good but was under-supported?
3. What would a skeptical reviewer attack first?
4. What supporting artifact should be prepared earlier next time?

## Ending Move

Always close by converting the debrief into:
- one or two durable rules
- one repeatable win
- one thing to stop
- one deliberate-practice next step
- one concrete collaboration-evolution recommendation
- one concrete tool-evolution recommendation
